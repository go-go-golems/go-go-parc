# P08 API Reference

## 1. Scope

The P08 API describes relations between endpoint values and procedures that restore those relations. It does not define component discovery, persistent port quotienting, authorization, network replication, or React rendering.

The trusted fragment is deliberately small:

```text
endpoint values
    + inspectable policy metadata
    + consistency judgment
    + typed repair outcome
    + deterministic scheduler
    + evidence and law fixtures
```

The implementation is in `src/`; `dist/` contains generated JavaScript and declarations.

## 2. Policy kinds

```ts
type PolicyKind =
  | "identity-reference"
  | "directed"
  | "asymmetric-lens"
  | "symmetric-consistency"
  | "delta-consistency"
  | "replicated-merge";
```

`replicated-merge` is included in metadata and taxonomy so that a replicated merge is not mislabeled as a lens. P08 does not implement it.

### 2.1 Identity reference

Use when both endpoints denote one logical resource and share the same update algebra.

```ts
const session = createIdentitySession(
  "primary-document-cell",
  ["chart.document", "pipeline.document"],
  { sort: "document", key: "doc-a" },
);
```

Every projection exposes the same `cellId`, revision, `get`, and `set`:

```ts
interface IdentityProjection<T> {
  readonly endpoint: string;
  readonly cellId: string;
  get(): T;
  revision(): number;
  set(value: T, actor?: string): IdentityWrite<T>;
}
```

An identity session is not a persistent topology compiler. The host must provide merge policy when previously independent values differ.

### 2.2 Directed policy

Use when one endpoint is derived from another and no inverse is semantically authorized.

```ts
const repair = directedReplacementPolicy.propagate({
  direction: "forward",
  left: { rows: ["row-7"] },
  right: { op: "true" },
});
```

A backward request returns `invalid` rather than inventing an inverse.

### 2.3 Asymmetric lens

An asymmetric lens has source `S`, view `V`, a `get : S -> V`, and a partial `put : S x V -> S`.

The artifact encodes both directions through `propagate`:

```ts
propagateForward(policy, source, currentView);
propagateBackward(policy, currentSource, editedView);
```

The selection/filter lens is total only on the exact-row fragment. Non-exact filter forms return a typed conflict.

### 2.4 Symmetric consistency policy

A symmetric policy starts with a relation:

```text
consistent : L x R -> Evidence
```

and permits both repair directions. It need not privilege either model as the source of truth.

```ts
const policy = symmetricSelectionFilterPolicy;
const judgment = policy.consistent(selection, filter);
```

Repair is representation-sensitive: it may preserve an inspectable envelope around the selection clause rather than replacing the entire target.

### 2.5 Delta policy

A delta policy receives old state, new state, and an edit description:

```ts
interface DeltaLeftState {
  readonly before: RowSelection;
  readonly after: RowSelection;
  readonly delta: SelectionDelta;
}
```

The delta is included in evidence even when the final extensional target is unchanged, such as a reorder that the filter representation cannot encode.

## 3. Policy metadata

```ts
interface PolicyMetadata {
  readonly id: string;
  readonly version: string;
  readonly label: string;
  readonly kind: PolicyKind;
  readonly leftSort: string;
  readonly rightSort: string;
  readonly description: string;
  readonly supportedDirections: readonly Direction[];
  readonly declaredLaws: readonly string[];
  readonly assumptions: readonly string[];
  readonly opaqueCallbacks: readonly string[];
}
```

Metadata is not decorative. The registry uses it for direction checks and sort-level introspection; the UI uses it for explanations; the capsule exports it as extensional data.

Policy IDs are versioned strings. A change to relation or repair semantics should use a new policy version.

## 4. Consistency evidence

```ts
interface ConsistencyEvidence {
  readonly consistent: boolean;
  readonly relation: string;
  readonly summary: string;
  readonly facts: readonly string[];
  readonly informationLoss: readonly string[];
}
```

A Boolean alone cannot explain why a pair is inconsistent or why a consistent relation is lossy. The selection/filter relation can be true while also reporting that a station summary loses individual row identity.

The reference relation compares filter denotation over the fixed row catalogue with the selected row set. Structural filter equality is not required.

## 5. Repair outcomes

```ts
type Repair<T> =
  | Updated<T>
  | Unchanged<T>
  | Conflict<T>
  | Invalid;
```

### 5.1 Updated

```ts
{
  kind: "updated";
  value: T;
  evidence: RepairEvidence;
}
```

The target must be replaced with `value` if the host commits the repair.

### 5.2 Unchanged

```ts
{
  kind: "unchanged";
  value: T;
  evidence: RepairEvidence;
}
```

The target already satisfies the policy, or the edit has no extensional representation. `unchanged` still includes evidence.

### 5.3 Conflict

```ts
{
  kind: "conflict";
  conflictKind:
    | "ambiguous-inverse"
    | "information-loss"
    | "concurrent-intent"
    | "non-convergent"
    | "policy-refusal";
  choices: readonly RepairChoice<T>[];
  evidence: RepairEvidence;
}
```

A choice is an explicit candidate, not a hidden fallback:

```ts
interface RepairChoice<T> {
  readonly choiceId: string;
  readonly label: string;
  readonly value: T;
  readonly score: number;
  readonly explanation: string;
  readonly informationLoss: readonly string[];
  readonly provenance: readonly string[];
}
```

Every row-selection choice generated by the inverse enumerator is tested to satisfy the requested filter relation.

### 5.4 Invalid

```ts
{
  kind: "invalid";
  reason: string;
  evidence: RepairEvidence;
}
```

Use for unsupported direction, malformed input, or policy-domain violation. Do not use `conflict` for an operation that is not defined.

## 6. Repair evidence

```ts
interface RepairEvidence {
  readonly evidenceId: string;
  readonly policyId: string;
  readonly policyKind: PolicyKind;
  readonly direction: Direction;
  readonly summary: string;
  readonly consistencyBefore: ConsistencyEvidence;
  readonly consistencyAfter: ConsistencyEvidence;
  readonly informationLoss: readonly string[];
  readonly preservedIntent: readonly string[];
  readonly discardedIntent: readonly string[];
  readonly provenance: readonly string[];
  readonly delta?: JsonValue;
  readonly assumptions: readonly string[];
}
```

Evidence IDs are session-local. `LinkPolicyRegistry` retains repair outcomes so `links.explain-repair` can retrieve them.

The evidence object is not a formal proof certificate. It is inspectable runtime evidence tied to tested policy semantics.

## 7. Conflict strategies

```ts
type ConflictStrategy =
  | "automatic"
  | "ranked"
  | "dialog"
  | "refuse";
```

```ts
resolveConflict(repair, strategy);
```

Rules:

- `automatic` chooses only when the top declared score is unique;
- `ranked` returns a pending ranked list;
- `dialog` returns pending choices for explicit selection;
- `refuse` declines repair.

Scores are application-specific evidence. They are not universal utility or proof of user intent.

## 8. Filter language

```ts
type FilterExpr =
  | { op: "true" }
  | { op: "inRows"; rows: readonly RowId[] }
  | { op: "stationIn"; stations: readonly string[] }
  | { op: "and"; args: readonly FilterExpr[] }
  | { op: "or"; args: readonly FilterExpr[] }
  | { op: "opaque"; id: string; label: string };
```

### 8.1 Normalization

`normalizeFilter`:

- deduplicates and sorts row IDs and stations;
- flattens nested conjunctions and disjunctions;
- removes neutral `true` clauses from conjunctions;
- deterministically sorts compound arguments.

Normalization supports stable evidence, scheduler hashes, and tests. It is not a complete Boolean-algebra normal form.

### 8.2 Denotation

```ts
filterMatchesRow(filter, row);
rowsMatchingFilter(filter, rows);
```

Opaque predicates are preserved but evaluate to true. Therefore denotational claims involving opaque clauses are partial and explicitly assumed.

### 8.3 Selection equivalence

Two equivalences are available:

```ts
selectionSetEquivalent(left, right);
selectionSequenceEquivalent(left, right);
```

Policy laws must state which one they use. The lawful-surprising lens is lawful under set equivalence and not under structural sequence equality.

### 8.4 Envelope preservation

`preserveEnvelopeWithSelection` locates an inspectable selection clause inside a compound filter and replaces only that clause. Unrelated clauses remain present.

`countPreservedClauses` is used by the comparative experiments.

## 9. Registry

```ts
const registry = createDefaultRegistry();
```

Key methods:

```ts
registry.register(policy);
registry.get(policyId);
registry.list();
registry.checkPolicy(policyId, direction?);
registry.propagate(request);
registry.explainRepair(evidenceId);
```

The registry:

- rejects duplicate IDs;
- validates requested direction before invoking a policy;
- stores repair evidence for explanation;
- does not dynamically search conversion paths;
- has no process-global singleton.

## 10. Propagation helpers

```ts
propagateForward(policy, left, right, context?);
propagateBackward(policy, left, right, context?);
```

These helpers retain the `left` and `right` semantic orientation even when propagation direction is backward.

## 11. Deterministic scheduler

```ts
const scheduler = new PropagationScheduler(registry)
  .declareNode({
    id: "selection",
    sort: "row-selection",
    value: { rows: ["row-7"] },
    revision: 0,
  })
  .declareNode({
    id: "filter",
    sort: "filter-expression",
    value: { op: "true" },
    revision: 0,
  })
  .declareEdge({
    id: "selection-to-filter",
    policyId: "row-selection-to-filter/0.1",
    from: "selection",
    to: "filter",
    direction: "forward",
    priority: 10,
  });
```

Run an atomic transaction:

```ts
const report = scheduler.transact(
  [{
    nodeId: "selection",
    value: { rows: ["row-7", "row-11"] },
    origin: "user",
  }],
  {
    conflictStrategy: "dialog",
    maxSteps: 64,
    commitOnStableOnly: true,
  },
);
```

`SchedulerReport.status` is one of:

- `stable`;
- `conflict`;
- `oscillation`;
- `bounded-failure`;
- `invalid`.

The schedule signature is derived from normalized edge order. Equivalent edge declarations produce the same signature regardless of declaration order.

### 11.1 Ordering

Edges are ordered by:

1. numeric priority;
2. edge ID;
3. target ID.

Changing this ordering is a semantic change and should be versioned or made explicit at composition time.

### 11.2 Loop detection

The scheduler hashes:

```text
normalized state + pending work signature
```

A repeated pair is reported as oscillation. A cycle with continually new values reaches the configured step bound and reports bounded failure.

### 11.3 Commit behavior

With `commitOnStableOnly`, any unresolved conflict, invalid repair, oscillation, or bounded failure returns the initial state and does not mutate the scheduler's committed nodes.

## 12. Law harness

```ts
const report = runLawHarness(20260808);
```

The harness includes:

- deterministic generators;
- domain-aware shrinkers;
- finite model enumeration;
- explicit equivalence relations;
- an expected negative control.

A law result identifies its evidence level:

```ts
"model-checked" | "property-tested" | "example-tested"
```

Do not reinterpret property-tested results as universal formal proofs.

## 13. Feedback simulator

```ts
simulateFeedback(
  FEEDBACK_SCENARIOS.find(
    scenario => scenario.id === "oscillating-mod3",
  ),
  24,
);
```

The supplied cases are:

- convergent normalization;
- modulo-three oscillation;
- unbounded divergence.

This simulator isolates scheduling behavior from row/filter policy details.

Request:

interface LabEnvelope<T = unknown> {

Response status:

### 14.2 Bounded identity-reference operations

The adapter supports enough `bindings.*` behavior to replay the common identity-link scenario. It compares selected contract fields and creates one in-memory `IdentityCell`.

This is intentionally not a replacement for P06:

- only one identity link is compiled;
- persistence and unlink topology are not implemented;
- distinct initial values use a documented left-endpoint policy because the common trace has no merge policy.

### 14.3 Unsupported operations

Out-of-scope operations return:

```json
{
  "status":"unsupported",
  "explanation":{
    "status":"unsupported",
    "summary":"... is outside the P08 bidirectional-link artifact boundary.",
    "completeness":"complete"
  }
}
```

## 15. React adapter boundary

The React file imports compiled policies and helpers. React owns:

- mounted occurrences;
- visual port cards;
- accept-mode endpoint selection;
- user-selected conflict choices;
- keyboard and pointer event adaptation.

The semantic kernel owns:

- relation evaluation;
- repair generation;
- evidence;
- law metadata;
- feedback simulation.

A host integrating P08 should preserve this separation.

## 16. Composition requirements

A future integrator must provide:

1. endpoint sort and contract information;
2. a selected policy ID and version;
3. authority to choose conflict strategy;
4. explicit scheduler ordering;
5. lifecycle behavior for stale endpoints;
6. persistence or replication semantics outside this artifact;
7. a UI for information-loss and ambiguity evidence.

The worst integration error is to create an identity link for unequal representations because their TypeScript payloads happen to be assignable.
