# Chapter 2 · Units Travel With Values

*Lengths, coordinate frames and value encodings are tags on values; conversions are explicit steps chosen by
declared rules, never silent.*

Rating: ★ (a good form among several; the variations name the others; see the overview).

## Intent

Make the meaning of a number part of the value that carries it: which unit a length is in, which coordinate frame a
position refers to, which encoding or scale a sample value is on. Operations declare which tags they accept and
produce; the system inserts the conversions between them, or refuses, so that no number is ever read on the wrong
scale.

## Also known as

Tagged quantities, units of measure, typed coordinate spaces, colour-managed pipeline, "no naked numbers".

## Motivation

A film scan arrives as a 16-bit TIFF. Its sample values are in file units, an encoded scale that is not
proportional to light. goja-cv must let an agent blur it, threshold it, measure specks on it and report positions
that a person can find in the original scan. Each of those steps has a scale on which it is correct:

- A **blur** or a **measurement of contrast** is physically meaningful only in linear light. On encoded values it
  weights dark and bright regions differently.
- A **threshold** like "brighter than 0.3" means different pixels on encoded and on linear values.
- A **radius of 3** means three pixels of the original scan, but the engine may compute a preview at a quarter of
  the resolution, where it is less than one pixel.
- A **position** reported from a cropped tile must still point at the right place in the full scan.

Without tags, the originating projects hit each of these. Two of the nine prototypes did not scale radii and crops
at export, so the full-size result differed from the approved preview. The dust project's gold labels stored a
radius that turned out to be a fitted radius, about twice the speck's own; measuring with it as if it were the
speck's radius gave a median signal-to-noise ratio of 0.86 instead of 1.56. Re-encoding the tiles when exporting
them changed which specks ranked highest. None of these failed loudly.

The same problem appears wherever numbers have more than one reading:

- A **geospatial service** mixes metres, degrees and coordinate reference systems; a buffer of "100" around a point
  in degrees covers most of a city.
- A **finance system** adds amounts in different currencies, or a percentage to a fraction.
- A **robotics stack** passes poses between the robot frame, the camera frame and the world frame.

## Problem

**When a number's unit, frame or scale lives only in the head of whoever wrote the code, a value read on the wrong
scale produces a plausible result instead of an error.**

## Forces

- **Convenience against correctness.** Plain numbers are easy to pass around; tags add ceremony to every call.
- **Automatic against explicit conversion.** Converting silently keeps scripts short but hides what happened;
  requiring explicit conversion is honest but verbose.
- **Kernel simplicity against kernel safety.** A kernel that assumes its input scale is simple and fast; a kernel
  that checks or converts is safer and duplicates conversion code across kernels.
- **One canonical scale against preserving the original.** Converting everything to one internal scale at load is
  simple, but saving results in the file's own units, or showing them to a person, needs the original scale back.
- **Strict frames against flexible composition.** Refusing to combine values from different frames prevents
  misalignment, and also blocks legitimate operations that a cheap conversion would allow.

## Solution

**Therefore: attach to every value the tags that decide how its numbers are read: the unit of its lengths, the frame
of its coordinates, the encoding of its samples. Give every operation a rule: it follows its input's tags, or it
works in a declared space (physical, display), or it needs inputs in one frame. Let the graph builder, not the
kernels, satisfy the rules by inserting explicit conversion steps, which are ordinary, cached operations; refuse when
no conversion is defined. Arguments carry units too, and the engine converts them to the scale it actually runs at.
Report results in the frame the caller can use.**

## Applicability

Use it when:

- the same quantity has more than one legitimate representation in the system (linear and encoded samples, metres
  and degrees, preview and full resolution);
- values cross boundaries where the reader cannot see where they came from (an agent, a saved file, another team's
  service);
- a mistake would produce a plausible but wrong result rather than a crash.

Do not use it when:

- every value in the system has one representation and always will; the tags would only add ceremony;
- performance-critical inner loops would have to check tags per element; keep the tags on containers (images,
  arrays), not on individual samples;
- the domain's conversions are lossy or ambiguous enough that automatic insertion would hide real decisions; then
  require explicit conversions and refuse instead of inserting.

## Structure

| Participant | Responsibility |
| --- | --- |
| **Tagged value** | Carries data plus tags: unit of lengths, coordinate frame, sample encoding or space. |
| **Operation rule** | Says per operation which tags it accepts, which space it computes in, and which tags its result has. |
| **Argument unit** | The unit of each numeric argument (document pixels, fractions, areas, levels on the receiver's scale). |
| **Builder** | Resolves rules at graph-construction time and inserts conversion steps, or refuses. |
| **Conversion step** | An ordinary operation (`as(space)`, reproject, rescale) that the graph caches like any other. |
| **Scale binder** | Converts argument units to the scale the engine runs at (preview, full resolution). |
| **Reporter** | Expresses results in the caller's frame (absolute document coordinates, the file's units). |

## Collaborations

1. A source opens with tags from its file: goja-cv's `cv.open` returns file units and the file's frame, with an
   optional origin so that a tile cut from a scan keeps the scan's coordinates.
2. The agent calls an operation. The builder reads the operation's rule: a physical operation (exposure, healing,
   conversion to grey by Rec. 709 weights) needs linear light, so the builder inserts `as("linear")` before it and
   converts the result back to the receiver's space.
3. Operations with several image inputs take the receiver's space; the builder converts the other inputs to it.
   Inputs from different frames are refused (`E_FRAME`), and mixing encodings in encoded space raises a warning
   (`ENCODING`).
4. At evaluation, the scale binder converts length arguments from document pixels to buffer pixels for the scale
   being computed, so a radius means the same thing at preview and at full size.
5. Results come back in document coordinates, which the caller can match against the original file.

## Sketch

```text
value Tags:   unit: Unit, frame: Frame, space: Space            -- e.g. docPx, [x, y, w, h], encoded | linear
value Image:  data, tags: Tags
value OpRule: works: follows | physical | display, needsSameFrame: bool, resultSpace: follows | linear | encoded

build(op, receiver, args) → Node | Refusal
  rule = op.rule(args)
  inputs = [receiver] ++ imageArgs(args)
  for x in inputs[1:]:
    if x.frame ≠ receiver.frame and rule.needsSameFrame:
      return refuse(E_FRAME, frames: [receiver.frame, x.frame], hint: "crop both alike")
  work = match rule.works:
    physical → linear
    display  → encoded
    follows  → receiver.space
  inputs = [convertNode(x, to: work) for x in inputs]          -- inserted nodes, hash-consed and cached
  n = node(op, inputs, args)
  return match rule.resultSpace:
    follows → convertNode(n, to: receiver.space)
    linear  → n
    encoded → n

convertNode(x, to: s) → Node
  if x.space == s: return x
  if no conversion from x.space to s: return refuse(E_SPACE, from: x.space, to: s)
  return node("as", [x], {space: s})

bindLength(arg, scale) → number                               -- at evaluation time
  match arg.unit:
    docPx    → arg.value × scale
    docPx2   → arg.value × scale²
    fraction → arg.value × extent(at: scale)
    level    → arg.value                                       -- read on the receiver's own scale

-- in use
img   = open("scan.tif", origin: [2048, 1024])                 -- file units, frame of the scan
glow  = img.exposure(+1)        -- builder inserts as(linear) → exposure → as(file units)
spots = img.as("linear").peaks(radius: 3)                      -- 3 doc px, whatever the scale
-- spots[i].cx, .cy are scan coordinates: the tile's origin is part of its frame
```

## Implementation notes

1. **Kernels never convert.** goja-cv's builder inserts conversion nodes; kernels assume their declared space.
   Conversion code then exists once, is cached like any node, and shows up in the graph an agent can inspect. The
   Editor lab does the opposite: its exposure and temperature kernels each convert to linear and back inside their
   loops. That works, but every new physical kernel must remember to do it.
2. **Put the space on the value, not in the caller's head.** goja-cv v1 chose the scale per call, through options;
   its v2 made the space a property of the image, set by `cv.open` and changed only by `as()`, with every other
   operation returning its result in its receiver's space. The scale of a number is then a fact the agent can read,
   not a convention it has to remember.
3. **Give threshold arguments a unit too.** A level such as "above 0.3" is read on the receiver's scale. Declaring
   that unit (goja-cv's `Level`) lets help say so and lets an agent convert deliberately
   (`img.as("linear").mask.luminance({ above: 0.3 })`).
4. **Areas scale with the square.** goja-cv's `DocPx2` unit scales by the square of the evaluation scale. A minimum
   area given in document pixels squared is otherwise a hundred times too strict at one-tenth scale.
5. **Frames are tags too.** A crop keeps the document coordinates of its source, and so does a tile cut from a scan
   if it is opened with its origin. The dust project's helpers open every tile at its origin, so every coordinate an
   agent reports is an absolute scan coordinate that the gold labels and the review tool share.
6. **Refuse combinations across frames; do not resample silently.** goja-cv's `E_FRAME` tells the agent to crop both
   inputs alike. Silent resampling would misalign masks and images by fractions of a pixel, which matters for
   specks that are three pixels wide.
7. **Tag the data you did not produce.** The gold labels' radius was the radius of a fitted circle, not of the
   speck. Nothing in the data said so, and every measurement made with it was wrong until someone compared the
   numbers with the pictures. A field's unit and definition belong next to it in the schema.
8. **Encoding chains are conversions too.** Exporting tiles with a different encoding changed the rankings of
   specks. Treat every re-encoding on the way to a dataset as a conversion step with a record, not as file
   plumbing.
9. **Warn where you cannot refuse.** Mixing encodings in encoded space is sometimes intended (a display overlay).
   goja-cv raises a build-time `ENCODING` warning instead of an error; the agent sees it next to the line that
   caused it.
10. **Keep the canonical scale internal and the original scale available.** goja-cv decodes to float internally,
    reports results in the receiver's space, and writes files in the requested encoding. Saving in the file's own
    units is a conversion step like any other.

## Variations

- **Static units in the type system** (units of measure in the compiler). Errors before running, no run-time
  cost; needs a language that supports it and does not cover data loaded at run time.
- **Canonicalise at the boundary.** Convert everything to one scale on load and back on save; nothing inside carries
  tags. Simplest, until two internal scales are both needed (linear for physics, encoded for display).
- **Explicit conversions only.** Tags are checked but never converted automatically; every mismatch is a refusal with
  a fix. More verbose, fully transparent; suits domains with lossy conversions.
- **Tags as metadata sidecars** for stored data (a schema with units and definitions per column), without run-time
  enforcement. Catches the dataset problems of notes 7 and 8, not the computation ones.

## Consequences

- \+ A whole class of plausible-but-wrong results becomes refusals or warnings.
- \+ Preview and full-resolution results agree, because arguments mean the same at every scale.
- \+ Conversions are visible, cached and testable, instead of scattered through kernels.
- \+ Coordinates survive cropping, tiling and export, so different tools can share positions.
- − Every operation needs a rule, and every new space needs conversions to and from the others.
- − Inserted conversions cost time and memory; a chain that bounces between spaces pays for each bounce.
- − Agents and users must learn the vocabulary (encoded, linear, document pixels) before the refusals make sense.

## Known uses

- **F# units of measure** check physical units at compile time; Python's **Pint** and **astropy.units** attach units
  to values at run time and convert between them.
- **OpenColorIO** declares colour spaces in a configuration and performs the conversions between them for film and
  visual-effects pipelines.
- **GDAL and PROJ** attach coordinate reference systems to rasters and vectors and reproject between them.
- The loss of **NASA's Mars Climate Orbiter** in 1999 followed from one team's software reporting impulse in
  pound-force seconds where another expected newton seconds, the classic case of a number without its unit.
