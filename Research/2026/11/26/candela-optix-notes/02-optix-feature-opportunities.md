# OptiX feature opportunities for Candela

When a studio artist changes the Singer camera, the primary rays change while the needle and hook retain their geometry. When the shaft turns, the parts change placement. When a section passes through the bobbin case, the cut introduces new triangles. A renderer can distinguish all three because it knows the camera, the part occurrences, and the meshes that define them. OptiX supplies operations appropriate to these changes. Candela decides which data to keep, which operation to request and how to validate the result.

This review uses the repository implementation and the Spark installation record from November 21, 2026. That record identifies the GB10, driver 580.178.04, and a successful OptiX SDK 9.0.0 sample. An SDK 9.1.0 build on the same installation reached an unsupported-ABI error at initialization. The documented runtime advertised ABI 110, the 9.0 build requested 105 and the 9.1 build requested 118. These are historical observations. Use the tagged 9.0 interface definitions when planning the experiments and record the device, driver, SDK, renderer build and feature probe with any new result. Source in Jig is `import/candela/native/rt/CMakeLists.txt` and the install receipt is `ttmp/2026/11/21/CANDELA-002--fast-candela-rendering-on-the-dgx-spark-gpu-browser-native-webgpu-runner-optix-backend/various/08-optix-sdk-install.txt`. [NVIDIA OptiX 9.0 API definitions](https://github.com/NVIDIA/optix-dev/blob/v9.0.0/include/optix_types.h)

## Where changes belong

| Opportunity | Existing code | Proposed work | An observable outcome |
|---|---|---|---|
| Instance updates for rigid motion | Per-mesh acceleration structures, instance descriptors, compaction | Persistent native ownership, explicit resource revisions, eligible in-place updates | A moving shaft reuses its mesh. A camera-only orbit issues zero geometry builds after initialization. |
| Temporal denoising | Single-frame OptiX AOV denoiser with beauty, albedo and normals | Motion-vector image, history buffers and restart rules for sequence edits | A low-sample preview exhibits less flicker while a passing highlight keeps its apparent speed and width. |
| Per-light render layers | One beauty layer sent to the AOV denoiser | Attribute radiance to light groups in Candela, accumulate and export linear layers, denoise jointly where useful | With fixed emitter positions, the artist adjusts fill intensity and sees the updated composite. |
| Native curves | Native triangles, custom bounded primitives, eligible built-in spheres | Export a strand description, configure the curve module, implement curve hit shading and an equivalent browser representation | A strand remains attached to the needle eye and is visible as the hook carries it around the case. |
| Reflection visibility and shutter motion | Instance visibility bits and rigid motion transforms already implemented | Define semantics for camera, secondary and shadow rays and export consistent shutter samples | A hidden studio emitter remains visible in metal reflections. A moving needle blurs over a specified shutter interval. |

## Accelerating a moving assembly

A geometry acceleration structure (GAS) indexes primitives in local coordinates. An instance acceleration structure (IAS) indexes placed occurrences. Candela’s `buildMeshes` creates a GAS for each populated triangle mesh. Its `buildAS` helper selects a build operation and can compact its result. Its `setFrame` frees the previous per-frame resources and creates new instance and auxiliary resources. The offline render path calls `setFrame` and uploads scene buffers when the aggregate scene version changes. The sampling code can keep using the resulting scene handle after the host-side policy is refined. Local implementation is in `import/candela/native/rt/src/optix_renderer.cpp`, `main.cpp` and `import/candela/src/engine/headless.ts`.

An update candidate starts with a build that explicitly allows updates. The worker retains the structure and allocates the scratch space reported for an update. For a transform-only change with compatible instance inputs, it supplies revised transforms and selects `OPTIX_BUILD_OPERATION_UPDATE`. It can retain unchanged mesh accelerators. Structural invariants include counts, build input types and the child handles referenced by an IAS. Geometry replacement can therefore require rebuilding its parent even if the instance count is unchanged. Log separate counts for untouched structures, updates and complete builds. [NVIDIA 9.0 acceleration structure types](https://github.com/NVIDIA/optix-dev/blob/v9.0.0/include/optix_types.h) · [OptiX programming guide, acceleration structures](https://raytracing-docs.nvidia.com/optix9/guide/optix_guide.250703.LTR.pdf)

Three workloads distinguish economic and geometric correctness. A static orbit exercises complete reuse. A moving shaft exercises rigid-instance updates. A cut through a wall exercises a change of connectivity or primitive count and the resulting parent update or rebuild. Compare first-hit identities, hit distances and silhouettes against a full rebuild, including shadow samples at the cap. Measure both build and trace time over the full sequence. Large changes of bounds can make a refitted structure slower to traverse, so the best update policy may differ between a low-sample preview and a high-sample final.

## Denoising a sequence

Candela’s native `AiDenoiser::run` supplies a linear beauty image, albedo and normal guides, and requests one output layer. A beauty image represents the combined light received by each pixel. An auxiliary output variable (AOV) records an additional quantity, such as diffuse light or reflected light. The current denoiser selects the AOV model and feeds one beauty layer. The Stage runner passes `--denoise scene`, which leaves the postprocessing choice with the scene configuration. The OptiX traversal backend and the AI denoiser have separate selection paths. See `import/candela/native/rt/src/denoiser.cpp`, `import/candela/native/rt/kernels/candela_post.cuh` and `scripts/render-stage-job.py`.

A temporal denoiser uses the previous denoised output and a per-pixel flow vector describing apparent movement. For a pixel on the needle, retrieve its visible hit point in the needle’s local coordinates. Project that point once with the previous needle pose and previous camera and once with the current pose and camera. The difference gives the previous-to-current pixel displacement at that point. Holding the camera fixed in this calculation would lose its orbital motion. Each output panel needs its own projection and ordered history. A camera cut, a switch of panel, or a discontinuity in frame order should start a fresh history. A newly exposed cap requires detection of missing correspondences. The guide API supports a trust image. Test the behavior at newly visible pixels before adopting one rejection policy for every shot. [NVIDIA temporal denoising and flow diagrams, chapter 16](https://raytracing-docs.nvidia.com/optix9/guide/optix_guide.250703.LTR.pdf) · [NVIDIA sample, history management and guide allocation](https://github.com/NVIDIA/optix-sdk/blob/main/SDK/optixDenoiser/OptiXDenoiser.h)

The native worker should persist previous output and internal guide buffers per panel at a known resolution. Record the selected model, reset decision, guide conventions and usable frame ranges in its receipt. One documentation detail requires a pinned-SDK test. The 9.0 `OptixDenoiserGuideLayer` declaration specifies world-space 3D normals for the models outside its LDR/HDR cases, while NVIDIA’s host API documentation describes camera-space normals for temporal models. Confirm behavior with a known moving-camera sequence and the actual SDK sample before introducing a conversion. Flow direction and indexing can be checked independently with a translation by an exact integer number of pixels. [NVIDIA 9.0 guide declaration](https://github.com/NVIDIA/optix-dev/blob/v9.0.0/include/optix_types.h) · [NVIDIA denoiser host API](https://raytracing-docs.nvidia.com/optix9/api/group__optix__host__api__denoiser.html)

In the stored CANDELA-002 experiment, 48 lockstitch frames at 1080p took 13.9 seconds wall time at 16 samples per pixel with spatial AI denoising, versus 44.9 seconds at 64 raw samples. Those runs changed both the sample count and the filter. They establish the time of two useful configurations. To evaluate temporal filtering, hold spp fixed and compare raw, spatially denoised and temporally denoised output against a high-spp sequence. Measure the needle-edge profile across frames, disocclusion remnants, and the location and width of the moving reflection. A highlight can move while the surface that reflects it stays still. This is why correct geometric flow alone does not settle whether the film looks right. The original record is `CANDELA-002/various/21-ai-denoiser.txt`.

## Multi-layer denoising and relighting

An editor who wants to increase fill light on a fixed subject needs the radiance attributable to the fill emitter, including its indirect contributions. The path integrator must accumulate it. OptiX can accept multiple image layers for denoising in one invocation. The application defines their meaning, assigns each path contribution and retains the desired precision. Group by emitter for studio relighting. Include the environment and unassigned emission in the decomposition. Grouping by material scattering type answers a different editing question and requires a different attribution rule. [NVIDIA 9.0 denoising guide, AOV layers](https://raytracing-docs.nvidia.com/optix9/guide/optix_guide.250703.LTR.pdf)

Establish that summing the *raw linear* groups with unit weights reproduces the beauty image with the same samples. With the camera, geometry, emission spectra and material properties fixed, doubling one emitter’s radiometric scale permits reweighting its group under linear light transport. Validate that edit against a fresh render with a reference noise estimate. Treat filtering, path contribution clamping, tone mapping and display color conversion as explicit stages. A moving strip changes shadowing and reflection positions, so it still requires new transport estimates. Candela’s area emitter update, optical integration and display processing already have distinct source entry points in `import/jigcad/src/render/studio-emitter.js`, `import/candela/src/engine/kernel.ts` and `import/candela/native/rt/src/post.cpp`.

## Representing thread as a native curve

The Singer is a useful acceptance scene for curve primitives because the thread must remain continuous through a small needle eye and be visible against polished metal. A proposed semantic input consists of a curve basis, connected segments, control vertices, radius values, a material and times at which those data change. A Jig author can initially declare a thread path as a function of shaft phase. Contact, slack and tension require mechanical or authored evidence of their own. The earlier K-09 path-traced lockstitch preset specifically records that it omitted the drawn thread of the original film. See `import/candela/content/presets/K-09-lockstitch.md`.

The native backend would pack control vertices, widths and segment indices for `OptixBuildInputCurveArray`, declare the chosen primitive type in pipeline compile options and obtain its built-in intersection module with `optixBuiltinISModuleGet`. A closest-hit program must recover the segment identity and curve parameter, derive the surface frame, and pass appropriate material and shading data to Candela. Current triangle shading relies on primitive records and barycentric coordinates, so the curve path needs its own surface reconstruction. A browser implementation can tessellate the same definition to an error tolerance or implement a software intersector. In either case the study’s unit conversion and radius convention must agree across backends. [NVIDIA 9.0 curve build inputs](https://github.com/NVIDIA/optix-dev/blob/v9.0.0/include/optix_types.h) · [NVIDIA device API](https://raytracing-docs.nvidia.com/optix9/api/group__optix__device__api.html)

Start with three fixtures: one straight round strand, one sharply turning loop, and one animated curve passing behind the hook. Compare endpoint caps, silhouette, shadow thickness, highlights and continuity across segment boundaries. Compare projected size and pixel coverage to a finely tessellated reference at the macro camera scale. At the distant full-head view, sampling and filtering of a subpixel strand can dominate smoothness independently of intersection accuracy.

## Existing controls with new uses

Candela already samples moving instance transforms through `OptixSRTMotionTransform` and passes a ray time during tracing. The Stage job command explicitly specifies `--no-motion-blur`. To offer shutter motion on a product film, export geometry and lights on a well-defined shutter interval, include the pose history needed by the backend, and decide how shutter integration interacts with the drafting plate. For an event hold at the needle scarf, protect the inspection frame from inadvertently integrating motion across the hold boundary. A useful regression compares a marked rotating crank at several shutter intervals with a stationary held crank. This separates motion blur inside one exposure from interframe denoiser flow. [NVIDIA 9.0 motion and instance types](https://github.com/NVIDIA/optix-dev/blob/v9.0.0/include/optix_types.h)

Current instance mask bits and ray masks distinguish shadow visibility. The non-shadow branch in `candela_traversal.inc` uses the same mask for a primary ray and its secondary bounces. A softbox that appears in polished metal while remaining outside the camera image needs a public visibility policy, an appropriate ray category on the device, and representative per-instance masks on the host. Explicit sampling of the area light must continue to use the intended direct-light semantics. Where multiple custom primitives share one masked instance, finer per-object policy needs regrouping or a change to the custom intersection program. Verify primary, reflected and shadow rays separately, followed by a full frame with a polished cylinder. [NVIDIA instance structure](https://raytracing-docs.nvidia.com/optix9/api/struct_optix_instance.html)

## Experiments to defer

Cluster acceleration structures expose lower-level construction options for workloads with large, changing triangle clusters. Cooperative vectors support device-side neural computation. The 9.0 interface provides capability queries for both. Start with a measured workload, a numerical baseline and an actual device capability result before implementing either. A small set of repeatedly posed CAD parts first calls for ordinary instance updates and resident geometry. A new neural material needs training data, an error budget, and a portable evaluation policy. Existing acceleration measurements already show workload dependence: on GB10 at 960 × 540 and 256 spp, shader execution reordering increased K-09 time by about 24% and reduced X-02 time by about 21% in the recorded experiment. See `CANDELA-002/various/22-ser.txt` and [NVIDIA’s 9.0 device properties](https://github.com/NVIDIA/optix-dev/blob/v9.0.0/include/optix_types.h).

For the first implementation, pair the resource change classifier with two native counters: mesh rebuild count and instance update count. A camera orbit, a rigid motion sequence and a topology-changing cut should produce distinct signatures. Follow with multi-layer outputs or curves according to whether the next user needs faster studio look development or a clearer account of stitch formation. Temporal reconstruction merits a sequence-level quality gate and an independently measured flow buffer before it becomes a review default.
